1. **子串回退的排序守卫**（`test_cjk_substring_ranking_is_identifier_then_shortest`）。此前 `ORDER BY 标识符命中 → 正文最短 → id` 无任何测试，而同一文件里 `test_fuzzy_fallback_pool_is_deterministically_bounded` 正是为防这类缺陷而存在。
2. **`FtsResult::is_widened_match()`**（新方法 + `test_widened_match_covers_both_arms`）。把「CJK 子串救援算作加宽匹配」这个隐式决定提成有名字的方法，并写下它在 MCP 面的两个后果：吃加宽惩罚（`CONF_OR_FALLBACK_PENALTY` 0.6，而非纯向量的 0.35），以及**不再触发**「无文本锚点」告警——因为子串命中确实是文本锚点。这两个后果本二进制（无 `embed-model`）都产生不出来，所以这是唯一钉住该决定的地方。
3. **单字 CJK 的取舍**（`test_single_cjk_character_still_searches`）。实测定案：`search 猫` 恰好命中 `猫咪管理`，`search 狗` 命中单字命名的符号，最坏情况 `search 的`（201 个文件全含）返回有界且确定序的列表。拉丁文那个 2 字符下限来自**分词器的存储规则**，对无分词器的子串扫描不成立——故保留，并用测试把这个不对称钉成有意为之。

变异验证 4/4 变红：抹掉标识符优先、抹掉正文长度优先、把 `||` 折叠成 `or_fallback`、给单字 CJK 加长度门槛。

### T2 — 快照信任模型

**更正**：我先前说这块「0 覆盖」是错的。`install.rs` + `tests.rs` 已有约 16 个专门测试覆盖完整性与信任两半（pin 匹配/不匹配/畸形、攻击者伪造 sidecar、无 pin 无 sidecar 的 fail-closed、重定向降级、解压炸弹、`resolve_rejects_untrusted_url_override`、`untrusted_origin_never_reaches_the_network`）。

真正的缺口只有一处，且是结构性的：`resolve_snapshot_source_impl` 把 `url_trusted` 当**参数**收，所有单元测试直接传布尔值；读环境变量的那层公开外壳 `resolve_snapshot_source` 无人触及。改错变量名、写反比较、复制粘贴成 `TRUST_ORIGIN`——整套测试照样全绿，而挡住恶意仓库快照注入的那道门会悄悄停止开启或停止关闭。

新增 `cli_snapshot_url_override_honors_only_its_own_env_signal`：通过真实二进制子进程跑 6 个用例（无信号 / `TRUST_URL=1` / `TRUST_ORIGIN=1` / `PIN` / `TRUST_URL=0` / `TRUST_URL=true`）。子进程而非 `set_var`，因为环境是进程全局的而其余套件并行跑。**`TRUST_URL=1` 是非空锚点**——没有一个被放行的用例，「全都被拒」既符合「门在工作」也符合「门接在没人设置的变量上」。端口 1 是保留端口，可信取回立刻连接被拒，离线确定。

## 已修复

**P1 CJK 检索失效** — `src/storage/queries/search.rs`（+ CLI/MCP 两个消费点）

- 现象：`search 订单` 对含「创建订单并扣减库存」的已索引节点返回 0 结果；整串查询却能命中。
- 根因：`nodes_fts` 用 `tokenize='porter unicode61'`，unicode61 把 CJK 表意文字全部归为 alphanumeric，因此无内部标点的整段 CJK 成为**单个 token**；FTS5 只匹配 token 与前缀，不匹配子串。
- 改法：`fts5_search_impl` 改为薄包装——MATCH 主体原样保留为 `fts5_search_match`，返回空且 `empty_reason` 为 None 时进入 `cjk_substring_scan`，仅对含未分词文字的 term 做 LIKE 扫描并 AND 连接，按「标识符命中优先 → 正文最短 → id」确定序排序。
- 理由：不改 schema、不动 INDEX_VERSION、不强制用户重建索引；只在原本已是死路（0 结果）的分支上加一条臂，ASCII 语义完全不变。

## 遗留风险与待办

**P2 tree-sitter `&raw`（需 §5 hard-AUTH，未修）**
借用名为 `raw` 的绑定（`&raw` / `&raw[..]` / `&raw.field`）被 `tree-sitter-rust` 0.23.3 误判为 `&raw const` 指针运算符的开头，整个表达式乃至外层函数从索引中消失。`&mut raw`、`&self.raw`、真正的 `&raw const x` 均正常。
实测（161 个 Rust 文件）：0.23.3 有 8 个文件 29 个 ERROR 节点、提取 3914 项；0.24.2 为 0 个文件 0 个 ERROR、提取 3915 项——**净损失 1 个符号**（`src/cli/commands/affected.rs` 的 `cmd_affected`，被 `main.rs` 调用）。
升级可行性已实测：`tree-sitter-rust` 0.24.2 需要 `tree-sitter` 0.25（0.24.7 下运行时报 `LanguageError { version: 15 }`），而 19 个语法 crate 在 0.25.10 下**全部加载成功**。
成本：prod 依赖 bump（§5 hard-AUTH）+ 19 种语言提取逻辑重新验证 + 很可能 INDEX_VERSION bump 强制全体用户重建。已在 README「Known limitations」中如实记录。

**待观察 — MCP 服务器偶发启动停顿**
早期约 60 次 `serve` 启动中有 2 次 >60s 无响应；此后 ~90 次（含 12 核满载）0 次复现，单独复现每个帧均在 50ms 内正确响应。按「复现不了的不修」标记，不做改动。若再次出现，先查 `.code-graph/index.lock` 持有者。
